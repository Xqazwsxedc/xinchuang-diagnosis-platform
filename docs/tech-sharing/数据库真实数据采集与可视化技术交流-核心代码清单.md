# 数据库真实数据采集与可视化技术交流：核心代码清单

## 使用建议

本清单根据《数据库真实数据采集与可视化技术交流》PPT 的数据采集、AI 故障预测和 API 分层主线整理。

现场讲解建议按下面顺序打开代码：

```text
API 入口 -> 业务编排 -> Prometheus 指标聚合 -> PromQL -> HTTP 查询 -> AI 异步执行 -> BentoML
```

## 第一优先级：数据库真实指标采集

对应 PPT 的“管理页面 -> Spring Boot 指标服务 -> Prometheus -> Exporter”链路。

| 顺序 | 文件 | 现场说明 |
| --- | --- | --- |
| 1 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/ledger/controller/LedgerDetailController.java` | 指标查询和 CSV 下载的 HTTP 接口入口 |
| 2 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/ledger/service/impl/LedgerDetailServiceImpl.java` | 校验数据库资源、监控配置，并编排指标查询 |
| 3 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/monitoring/prometheus/DbPrometheusMetricsService.java` | 聚合 CPU、内存、IOPS、连接数、缓存命中率，并转换为页面 VO |
| 4 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/monitoring/prometheus/PrometheusQueryFactory.java` | 集中生成 PromQL，区分 node_exporter 和 mysqld_exporter |
| 5 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/monitoring/prometheus/PrometheusHttpClient.java` | 调用 Prometheus `/api/v1/query` 和 `/api/v1/query_range` |
| 6 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/monitoring/prometheus/PrometheusResponseParser.java` | 解析 Prometheus 的 vector/matrix 响应并处理异常数值 |
| 7 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/monitoring/prometheus/PrometheusRangeResolver.java` | 将 `1H`、`1D`、`7D` 等业务范围转换为查询时间范围和 step |

## 第二优先级：AI 故障预测闭环

对应 PPT 的 BentoML、预测流程和异步执行链路。

| 顺序 | 文件 | 现场说明 |
| --- | --- | --- |
| 8 | `apps/api-server/src/main/java/com/xinchuang/diagnosis/ai/controller/FaultPredictionTaskController.java` | 故障预测任务的查询、新增、编辑、删除和立即执行接口 |

## 现场表述建议

> 数据采集部分由 Spring Boot 统一访问 Prometheus，PromQL 由查询工厂集中管理，响应由客户端解析后交给指标聚合服务，最终返回数据库详情页所需的稳定 DTO。AI 部分通过异步执行编排器获取 Prometheus 历史数据，调用独立 BentoML 模型服务，并将执行状态和预警结果回写平台。

需要特别说明：当前模型服务使用的是用于工程闭环验证的 Z-Score 时序异常检测模型，不应直接表述为生产级未来故障预测模型。
