本轮在既有测试基线之上扩展白盒和黑盒用例，不替换 `api-blackbox-test.ps1` 的 1.0 冒烟基线。重点覆盖数据台账关联约束、请求参数校验、系统管理只读链路、AI 数据壳查询，以及 admin、operator、viewer 三类角色的权限边界。

覆盖内容：

- 健康检查、未认证接口 `401`、admin 当前用户与五项系统管理菜单。
- 管理员查询用户、角色、安全日志、配置、字典、菜单、登录日志、操作日志、通知和数据大屏。
- AI 概览、模型、知识库、任务、故障/缺陷/优化报告的只读查询。

- operator 可查看台账，但查看用户和角色均返回 `403`。

项目业务异常采用统一响应体业务码，非法参数场景的 HTTP 状态为 `200`、响应体 `code=400`；2.0 脚本按该既有接口契约断言。

## 5. SonarQube 状态

本轮已完成 `mvn verify` 并生成新的 Surefire 与 JaCoCo 报告。提交 SonarQube 2.0 扫描时，本机 SonarQube 返回 `401 Not authorized`，现有管理员凭据或扫描权限已发生变化。为避免绕过认证或重置安全配置，本轮未伪造 SonarQube 指标。

待获得具有“Execute Analysis”权限的临时 SonarQube 令牌后，执行 `mvn sonar:sonar -Dsonar.host.url=http://localhost:9000 -Dsonar.login=<临时令牌>`，读取质量门禁后补充 `sonarqube-quality-report-2.0.md`。令牌不得写入项目文件，使用后必须撤销。
