## 4. 风险说明与处理建议

1. 质量门禁通过不代表全项目已达到生产质量目标。全项目覆盖率 8.4%、重复行密度 20.0% 和 65 个代码异味均为存量治理项。
2. 后续优先为系统管理、数据台账和 AI 服务的复杂分支补单元测试，将存量核心逻辑覆盖率逐步提升到 60% 以上。
3. 对新增或修改代码保持新增覆盖率不低于 80%，并在合并前处理新增代码异味。
4. 本机 SonarQube 启动日志显示默认管理员凭据仍在使用。该问题不影响本次扫描结果，但必须在用于多人或网络环境前修改 SonarQube 管理员密码；扫描令牌应临时生成并在扫描后撤销。

## 5. 复跑顺序

1. 在 `apps/api-server` 执行 `mvn verify`，生成 Surefire 与 JaCoCo 报告。
2. 启动本机 SonarQube，确认 `http://localhost:9000/api/system/status` 为 `UP`。
3. 使用临时 SonarQube 用户令牌执行 Maven Sonar 扫描；本机 Maven 插件 `3.10` 使用兼容参数 `sonar.login` 传入令牌。
4. 等待计算引擎完成，读取质量门禁和指标；扫描后立即撤销令牌。

令牌、管理员密码和数据库密码不得写入源码、脚本、报告或版本库。
