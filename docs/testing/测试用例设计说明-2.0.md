# 测试用例设计说明 2.0

## 1. 文档目的

本文档定义信创数据库智能故障诊断及修复平台的测试用例 2.0，按白盒测试和黑盒测试、再按模块功能分类组织。测试对象为当前一期版本的基座、系统管理、数据台账和 AI 数据壳。

## 2. 测试范围与约定

### 2.1 测试类型

| 类型 | 目标 | 执行方式 |
| --- | --- | --- |
| 白盒测试 | 验证服务内部逻辑、异常分支、审计调用、数据关联约束和 DTO 校验 | JUnit 5 + Mockito + JaCoCo，执行 `mvn verify` |
| 黑盒测试 | 验证真实 HTTP 接口、认证、权限边界、参数返回结构和部署代理链路 | PowerShell 调用 `http://localhost/api` |
| 页面集成测试 | 验证浏览器登录、菜单、路由和页面数据加载 | 见 `frontend-integration-checklist.md` |

### 2.2 黑盒测试前置条件

1. Windows 部署版已启动，`http://localhost` 与 `http://localhost/api/health` 可访问。
2. MySQL 演示数据中存在 `admin`、`operator`、`viewer` 三个内置账号，以及至少一条业务系统和分布式数据库资源。
3. 执行前在当前 PowerShell 会话设置 `DIAGNOSIS_TEST_PASSWORD`，脚本不保存任何账号密码。
4. 黑盒测试只允许成功执行查询、登录和预期被拒绝的写请求；不允许成功新增、修改、删除或下载，以免污染演示数据和审计记录。

### 2.3 结果判定约定

- 正常响应：HTTP `200` 且响应体 `code=200`。
- 未认证：HTTP `401`。
- 无权限：HTTP `403`。
- 项目参数校验错误：HTTP `200` 且响应体 `code=400`，这是当前统一业务响应契约。
