# Non Functional Requirements

## Source Summary

Word 需求中的非功能要求包括：

- 统一用户界面和操作流程，提高用户体验。
- 通过账号密码进行身份鉴别。
- 登录后所有操作和信息查看必须进行严格权限控制。
- 保证数据一致性、完整性和准确性。
- 对人工输入和接口数据进行合法性检查。
- 错误数据应自动纠错或提醒人工干预。
- 资料录入成功率和数据一致性、完整性、准确性要求达到高标准。

## Current Status

已实现的基础能力：

- 统一后台布局和 Element Plus 组件风格。
- JWT 登录认证。
- BCrypt 密码存储。
- 动态菜单和按钮权限。
- 后端接口权限拦截。
- DTO 参数校验。
- 前端表单校验。
- 统一返回结构。
- 统一异常处理。
- 操作日志和登录日志。

仍需增强：

- 更完整的自动纠错规则。
- 更细的测试覆盖率。
- 真实数据采集链路的一致性校验。
- 生产级数据备份、恢复和高可用。
- 登录失败锁定、密码策略和会话策略。

## Validation Principle

任何新功能必须至少满足：

- 后端入参校验。
- 前端表单校验。
- 后端业务约束校验。
- 枚举值白名单。
- 写操作审计。
- 构建或测试验证通过。
